# TD-03 暫時封存紀錄（2026-09-01）

## 狀態

TD-03 為「部分完成、暫時封存」，不是完成結案。封存的是尚未具備外部條件的 Redis 實連、雙
worker staging、觀測期與 rollout；既有 offline contract、canary、gate 與 rollback 證據不刪除。

2026-09-01 依重新授權啟動 workspace 隔離 Redis，完成本機 real probe、production shared-mode
integration 與雙 process probe，並將 Redis client protocol 固定為相容的 RESP2；此新增證據不
解除 production 封存，因 backup／restore、正式 provider staging、觀測期與人工 rollout approval
仍未完成；另已完成兩個獨立 `app.py` HTTP worker 的 staging canary。詳見
 [`TD-03 local Redis staging evidence`](TD03_LOCAL_REDIS_STAGING_EVIDENCE_2026-09-01.md)。

## 已保留的安全狀態

- `app:app` 與單 worker 執行契約維持不變。
- `Procfile`／`render.yaml` 維持 `--workers 1`。
- rate limit、cache L2、single-flight、background lease 等 shared mode 維持 `local`，不建立
  Redis connection、不切換正式部署。
- H-05／H-11 的 offline evidence、`eligible=false` rollout gate、既有測試與 rollback runbook 保留。

## 未完成但封存的範圍

1. 真實 Redis endpoint／secret store、PING／TTL、backup／restore 與 JSON-safe bucket 實連驗證。
2. 雙 worker staging 的 rate-limit consistency、single-flight、lease takeover／fencing、latency
   與 disconnect／fault evidence。
3. observation period、人工 rollout approval，以及任何 production worker／部署設定變更。

## 解封條件

必須重新取得明確授權，並具備隔離 staging Redis URL、provider／region／namespace、backup／restore
owner、完整實連與雙 worker canary 證據、觀測期與人工核准。解封後仍須先通過 rollout gate，才能
評估 shared mode 或 worker 數變更。

## 回退

任何未來解封批次失敗時，關閉 shared modes 回到 `local`、恢復單 worker `--workers 1`，回退單一
adapter／deployment commit；不修改 SQLite 或 `twse-cache.json`。
