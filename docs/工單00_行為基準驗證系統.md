# 工單 00:行為基準驗證系統(所有重構的前置條件)

> 目的:在動任何重構之前,對「原版」建立完整的行為快照。
> 之後每個 TD 工單完成時,重構版必須與快照完全一致才算通過。
> 本工單完成前,禁止執行任何 TD-01 ~ TD-13 的重構。

## 產出物

建立 `regression/` 目錄,包含:

```
regression/
├── capture_baseline.py    # 抓取基準(只在原版跑一次)
├── verify_against_baseline.py  # 比對現版與基準(重構期反覆跑)
├── frontend_check.py      # Playwright 前端檢查
└── baseline/              # 基準資料(commit 進 git)
    ├── api/               # 各 API 端點的 golden response
    ├── screenshots/       # 21 頁基準截圖
    └── manifest.json      # 端點清單、雜湊、抓取時間
```

## 第一部分:API 行為基準

1. 掃描 app.py 的全部 48 個 `@app.route`,列出完整端點清單。
2. 啟動本地伺服器(`python app.py`),對每個 GET 端點抓取回應,
   存為 `baseline/api/<端點名>.json`。
3. **時變欄位正規化**:回應中的時間戳、抓取時間、隨機 ID 等欄位,
   比對前必須遮罩(替換為 `<DYNAMIC>`),否則永遠比不過。
   先抓兩次間隔 10 秒的回應、diff 找出時變欄位,建立遮罩規則
   存入 manifest.json。
4. 需要參數的端點(如個股查詢),用固定測試參數:
   台股 2330、0050;美股 AAPL。參數組合記入 manifest.json。
5. 外部資料源(TWSE/TAIFEX/Yahoo)不穩定時:以 HTTP 狀態 +
   回應結構(JSON schema)比對取代全值比對,並在 manifest 標記
   該端點為 structure-only。

## 第二部分:前端行為基準(Playwright)

1. 安裝:`pip install playwright && playwright install chromium`
2. 對全部 21 個 HTML 頁面,無頭瀏覽器逐頁執行:
   - 頁面載入後等待 networkidle
   - **JS console 零 error**(warning 可容忍,error 即 fail)
   - 記錄頁面上可見的關鍵元素數量(卡片、表格列、canvas)
   - 全頁截圖存入 `baseline/screenshots/`
3. 比對模式:
   - console error:嚴格比對(基準為零,重構後也必須為零)
   - 元素數量:允許 ±0(結構必須一致)
   - 截圖:像素差異率 > 2% 即 fail(數據時變造成的小差異可容忍)
4. 特別驗證點(對應既有功能):
   - index.html:市場總覽卡片有渲染
   - tw-stocks.html:個股列表非空
   - futures.html / options.html:期權資料表有載入
   - K 線圖頁面:canvas 元素存在且非空白

## 第三部分:安全不變量檢查

寫入 `verify_against_baseline.py` 的固定檢查:
1. `python security_guardrail_check.py` 必須通過
2. 靜態掃描:execute() 內不得出現 f-string 或字串拼接
3. app.js 的 escapeHtml 呼叫次數不得低於基準值(2,037)的 95%
4. 回應標頭:CSP、X-Frame-Options、HSTS 必須與基準完全一致

## 第四部分:整合到工作流程

1. 在原版(重構前的 commit)執行 `capture_baseline.py`,
   基準檔 commit 進 git,tag 為 `baseline-v1`。
2. 修改 `.claude/settings.json` 的 Stop hook,追加執行
   `python regression/verify_against_baseline.py --quick`
   (quick 模式:跑「快取型端點」API 比對 + 安全檢查;TD-17 修復後只比對
   有快取層的 40 個端點,且比對前先明確暖身一次快取,實測約 1-2 分鐘,
   不再受外部資料源逐一逾時拖累)。
   `live-sectors`/`live-overview`/`live-stocks`/`live-search` 這 4 個
   設計上永遠直接打外部、無快取層的端點移到獨立的 `--api-live` 旗標
   (TD-17),`--quick` 預設不含,`--full` 自動包含。
3. 每個 TD 工單的完成定義(Definition of Done):
   - `python -m unittest test_derivatives_platform.py` 全綠
   - `python regression/verify_against_baseline.py --full` 全綠
     (full 模式:含 --api-live 即時端點比對 + Playwright 前端檢查)
   - 以上任一項失敗,該工單不得 commit。

## 驗收標準(本工單自身的 DoD)

- [ ] 在未修改任何程式碼的原版上,`verify --full` 必須 100% 通過
      (自我一致性:基準對照自己必須全綠,否則比對邏輯有誤)
- [ ] 故意注入一個測試錯誤(例如改掉一個 API 回傳欄位名),
      verify 必須抓到並 fail,改回後恢復全綠(驗證器有效性證明)
- [ ] README 增補 regression/ 的使用說明

## 注意事項

- baseline/ 內容一旦建立即凍結,重構期間禁止更新基準;
  若比對失敗,修的是程式碼,不是基準。
- 唯一例外:確認是基準抓取瑕疵(如漏遮罩時變欄位)時,
  可修正遮罩規則後重抓,需在 commit message 說明原因。
- 外部資料源當機造成的 fail,重跑一次確認;連續 fail 才視為真錯誤。
