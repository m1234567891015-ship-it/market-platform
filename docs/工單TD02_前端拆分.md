## 1. 本工單的核心約束(先讀,違反即整批退回)

1. **不導入任何建置步驟**。不使用 esbuild / Vite / rollup / webpack,不新增 `package.json` 建置腳本。拆分後仍是純靜態檔案,由 HTML 以多個 `<script>` 依序載入。
2. **CSP 不得退化**。`script-src 'self'` 維持不變,禁止為了拆分方便加入 `unsafe-inline` 或 `unsafe-eval`;禁止新增任何 inline `<script>` 內容(`<script src=...>` 標籤本身可新增)。
3. **`escapeHtml()` 維持單一來源**。拆分後全專案只能有一份定義,所有模組共用;不得複製多份。目前呼叫數約 2,037 次,拆分前後數量不得減少。
4. **不修復任何既有 bug**。TD-15(死碼與失效控制項)、TD-16(stack overflow)、TD-17 一律不動,發現新問題記錄不修。
5. **不改變外觀**。21 頁截圖 pixel diff 必須維持通過;若某次拆分導致 diff,一律修程式碼,不更新基準。
6. **不改變互動行為**。93 條互動路徑必須全綠。

## 2. 命名空間方案變更(第一部分盤點後修正)

原訂本節的技術風險假設——`app.js` 是「單一 IIFE」——經第一部分實測證實
不成立(見 `docs/frontend_module_map.md` 發現①):app.js 其實是 classic
script(無 `type="module"`、無 IIFE 包裹),全部頂層 `function`/`let`/
`const` 宣告本來就共享同一個全站 script 作用域,從未依賴單一閉包。只要
各 `<script>` 標籤依正確順序載入,跨檔引用天然不會斷裂——不需要
`window.MP` 命名空間,不需要改寫任何函式定義或呼叫點。

**原本指定的 `window.MP` 命名空間方案予以撤銷**,改用純粹的檔案切分:

1. **符號維持原本的頂層宣告,不包裝、不改任何引用點**。每個批次的操作
   純粹是「剪下 → 貼上到新檔案 → 調整 HTML 的 `<script>` 順序」,不重新
   命名、不加前綴、不包 IIFE、不掛到任何命名空間物件——每批次都是這樣
   一個純機械動作,不是高風險修改。
2. **每個符號在全站只能宣告一次**。`let`/`const` 重複宣告會直接
   `SyntaxError`,語法層面立即失敗,列入第 6 節第 1 層驗證。
3. **載入順序即依賴順序**(沿用,未變):於各 HTML 中明確排列,不得依賴
   hoisting。**新增檢查重點(見第 6 節第 6 層)**:確認沒有任何檔案的
   「頂層立即執行程式碼」(不是函式定義本體,是 `<script>` 執行當下就會
   跑的陳述式)引用到「更晚載入」的檔案中宣告的符號。函式定義本體內部
   引用晚載入檔案的符號是安全的(呼叫時機在全部 `<script>` 載入完畢
   之後才會發生)——`docs/frontend_module_map.md` 第 2 節末段已有一個
   驗證過的實例(`page-tw` 的 `initWatchlistPage` 呼叫 `main` 模組的
   `loadLiveData`,安全)。要特別檢查兩處立即執行程式碼:`state.js`
   開頭的初始化陳述式(如 `let data = window.TWSE_DATA || null;`)、
   `core.js` 內 `enforceSafeInnerHtml()` 那個獨立 IIFE。
4. **全域污染檢查改為「切分前後必須完全相同」**,不是原本「僅允許 `MP`
   一項」(已無 MP)。比對方式:Playwright 載入頁面後擷取 `window` 自有
   屬性集合 + 全域識別字綁定,切分前後逐項相同,任何差異都視為破壞
   (詳見第 6 節)。

## 5. 切片執行規範(每個切片一律照此流程)

沿用 TD-01 已驗證的節奏:

```
1. 特性化:為本批次要搬的函式,確認既有互動測試已覆蓋其路徑;
   若某函式無任何測試覆蓋,先補一條最小互動或渲染斷言,
   在現行 master 上跑到綠燈,再開始搬移。
2. 搬移:純位置移動(剪下 app.js 對應行 → 貼上到目標檔案)。
   不重新命名、不包裝、不掛命名空間、不合併、不優化、不刪除死碼。
3. 調整 HTML:更新受影響頁面的 `<script>` 標籤順序,新增指向目標
   檔案的 `<script src="js/*.js">`;呼叫端程式碼本身不需要任何修改
   (符號名稱不變,詳見第 2 節)。
4. 六層驗證(見第 6 節)全綠。
5. 獨立 commit,message 註明批次編號與搬移的符號數量。
```

**`renderStockDetail` 專屬規則**:此函式實測 2,512 行(`app.js:30029-32540`,
原工單估計 2,376 行,已依實測修正),獨立為一個批次,且**排在所有頁面
批次之後、`main` 批次之前**。搬移前先在 `docs/frontend_module_map.md`
中列出它內部的區段結構(渲染 / 資料處理 / 事件綁定),搬移時整體移動不
做內部拆分——內部拆分另立工單。

**單一切片規模上限**:一次不超過 60 個函式或 3,000 行。超過就再切薄。

## 6. 六層驗證(前端版,盤點後新增第 6 層)

每個批次 commit 前必須全綠:

| 層 | 指令 | 檢查什麼 |
|---|---|---|
| 1 | `node --check js/*.js` | 語法(含重複宣告的 `SyntaxError`) |
| 2 | `python -m unittest test_derivatives_platform.py` | 後端未受影響 |
| 3 | `python security_guardrail_check.py` + escapeHtml 計數 + CSP 標頭 | 安全不變量 |
| 4 | `python e2e_smoke.py` | 端到端可啟動 |
| 5 | `python regression/verify_against_baseline.py --full` | API 基準 + 21 頁截圖 + 93 條互動路徑 |
| 6 | 載入順序初始化檢查(新增,見下方) | 頂層立即執行程式碼沒有引用到晚載入檔案的符號 |

**追加檢查(本工單特有)**,納入第 3 層:

- **全域污染檢查**:於 Playwright 中載入頁面,擷取 `window` 自有屬性集合
  + 全域識別字綁定,與基準快照比對,**切分前後必須逐項相同**(已無 MP,
  不是「僅允許 MP 一項」)。
- **escapeHtml 單一來源檢查**:全 repo `grep -c "function escapeHtml"` 結果必須為 1。
- **inline script 檢查**:21 頁 HTML 中 `<script>` 標籤不得含有內容(僅允許 `src` 形式)。

**第 6 層:載入順序初始化檢查**(新增,獨立層,不與第 3 層混在一起跑):

1. 對每個已搬移的檔案,靜態掃描其「頂層立即執行陳述式」(不是函式定義
   本體內的程式碼,是 `<script>` 執行當下就會跑的陳述式——例如
   `let data = window.TWSE_DATA || null;` 這種立即求值的初始化),確認
   引用到的符號全部定義在「同一檔案內」或「載入順序更早的檔案」。函式
   定義本體內部引用晚載入檔案的符號視為安全,不算違規(理由見第 2 節
   第 3 點)。
2. 特別檢查 `state.js` 開頭的初始化陳述式與 `core.js` 的
   `enforceSafeInnerHtml()` IIFE——這是全站最早執行的立即執行程式碼,
   風險最高,每批次都要重新確認沒有新增違規。

以上四項檢查(全域污染、escapeHtml 單一來源、inline script、載入順序
初始化)在批次 1 開始前先實作,加入 `security_guardrail_check.py`。
