# TD-09 行為變更說明(回顧補課)

> 依 CLAUDE.md「硬性規則」新增條款補交:TD-09(重新啟用 service worker)屬於
> 「行為變更」型工單,執行時尚未有此規則,故於事後以此標準補交說明。
> 對應 commit:`3d9c3c2`(feat(TD-09): re-enable service worker with
> stale-while-revalidate static caching)。

## 1. 實際採用的快取策略細節

- 重新啟用 Service Worker,cache 名稱
  `market-pulse-swr-20260720-1-runtime`(`CACHE_VERSION =
  "market-pulse-swr-20260720-1"`)。
- 策略為 **Stale-While-Revalidate**,只套用在「同源 + GET + 副檔名屬於允許
  清單」(`.html`/`.js`/`.css`/`.svg`/`.png`/`.webmanifest`)的靜態資源。
  `/api/*` 一律不快取(維持即時性),跨網域請求(Google Fonts 等)完全不
  攔截、直接交還瀏覽器原生處理(不呼叫 `respondWith()`)。
- 行為:命中快取立即回傳,同時背景重新 fetch 更新快取供下次使用;無快取
  則等待網路回應,`response.ok` 才寫入快取;網路失敗且無快取則讓該次
  fetch 的 rejection 自然拋出,未另做離線後備頁。
- `activate` 階段只清除「非目前版本」的舊快取(原本每次啟動會把剛寫入的
  也一併清空)。`install` 呼叫 `self.skipWaiting()`、`activate` 呼叫
  `self.clients.claim()`,讓新版本立即接管現有分頁,不需使用者關閉分頁
  或手動重新整理。
- 同步修正 `pwa.js`:原本只會登出(unregister)任何已註冊的 SW、清空所有
  Cache Storage,從未真正呼叫過 `navigator.serviceWorker.register(...)`。
  這次補上 `registerServiceWorker()`,並保留原本「版本號變更時全部清除
  再重建」的機制作為未來事故的緊急開關。

## 2. 影響範圍(訪客瀏覽器快取行為)

- 首次造訪不受影響:SW 註冊本身是非同步的,會晚於瀏覽器已經開始抓取
  app.js/styles.css 等資源,所以第一次載入不會被攔截快取(標準 SW 生命
  週期行為,非 bug)。
- 從第二次載入起(SW 已 `activate` 並透過 `clients.claim()` 接管分頁):
  頁面殼、app.js、styles.css、pwa.js、manifest.webmanifest、SVG/PNG 圖示
  等會被快取到瀏覽器的 Cache Storage(獨立於 HTTP cache,不受伺服器目前
  `Cache-Control: no-store` 標頭影響),之後同源請求會先回傳快取內容,
  同時背景仍會重新 fetch 更新。
- `/api/*` 即時行情資料完全不受影響 — 明確排除在快取範圍外,一律直接
  打網路,不快取、不延遲。
- 第三方跨網域資源(Google Fonts 等)完全不受影響 — SW 不攔截,交還瀏覽
  器原生處理(此次同時修正的 bug:原本用 `respondWith(fetch(request))`
  轉發會讓跨網域字型請求出現 `net::ERR_FAILED`,已改為對非快取範圍的
  請求完全不呼叫 `respondWith()`)。
- 訪客離線時,已快取過的靜態資源(頁面殼、CSS、JS)可離線顯示,但即時
  行情資料仍需要網路,離線時只會呈現「資料無法載入」的既有行為,不會
  假裝有離線資料。
- 未改變任何頁面外觀或 DOM 結構:`verify --full` 的截圖比對在沒有重新
  校準基準的情況下直接通過(pixel diff 0),證實純粹是網路快取行為變更,
  不影響渲染內容。

## 3. Revert 路徑(如何安全退場舊 SW)

- 最直接:`git revert 3d9c3c2`(或還原 TD-09 之前的 `pwa.js`/
  `service-worker.js`),等同回到「SW 從未真正被註冊過」的狀態 — 因為
  退場邏輯本來就已內建在 `pwa.js` 的版本比對機制裡,不需另外設計新的
  退場程式碼。
- 若要在不 revert 程式碼的情況下「遠端退場」現有訪客的 SW:比照 `pwa.js`
  內建的版本比對機制,遞增 `VERSION` 常數即可 — 訪客下次載入會偵測到
  localStorage 記錄的舊版本號不同,自動觸發 `unregisterServiceWorkers()`
  + `clearBrowserCaches()` 全清後才重新註冊(見本文件下方「部署注意事項
  同步異動」)。
- 若要「徹底停用不留 SW」:
  1. 在 `pwa.js` 的 `syncRuntimeVersion()` 中移除
     `registerServiceWorker()` 呼叫,只保留 unregister/clear;
  2. **務必同步遞增 `VERSION`**,否則已記錄過目前版本的訪客瀏覽器不會
     觸發清除流程,SW 會持續留在瀏覽器上直到自然過期或使用者手動清除。
- 伺服器端所有靜態檔案(含 `service-worker.js` 本身)已一律下
  `Cache-Control: no-store`,所以新版 `pwa.js`/`service-worker.js` 一定
  會在訪客下次連線時立即抓到,不會被瀏覽器 HTTP 快取卡住,退場可以很快
  生效(不像 Cache Storage 需要靠版本比對機制主動清除)。
